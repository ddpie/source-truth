# 术语表：让中文提问命中英文代码

## 解决什么问题

策划用中文问（「成就怎么算」「掉率配在哪」），但代码是英文（`Achievement`、`loot_chance`）。
直接拿中文去搜代码，往往只命中注释，或完全搜不到。**术语表**把中文业务词映射到代码里真实
出现的英文符号，agent 据此把中文问题转成代码检索词。

它只是**额外的检索线索，不是答案**——只负责「该搜哪个英文词」，结论仍以实际查看代码为准。

> 本文偏 agent 接入（查询期工具、规则）。构建流程、产物结构、置信度依据的面向人说明见
> [`../glossary.md`](../glossary.md)。

## 怎么工作

分两段，对应上图左右两半。

**构建期（index 主机，离线）**——不在用户请求路径上，跟 git 刷新同节拍：
1. 扫本地代码副本中的候选文本文件：首次全量，配置不变时按 `git diff` 只扫变更文件。
2. 按项目 `agent.sdk` 使用 OpenAI Agents SDK 或本地 `claude` CLI，产出「中文词 ↔ 英文符号」
   对照（JSONL）。OpenAI 只提供当前批次的分页文件读取工具；Claude 保留原工具禁用与配置隔离。
3. **grounding 校验**（确定性把关）：一个中文别名只有真实出现在源文件里才保留，否则丢弃——
   挡掉模型自己「翻译/臆造」出来的词。文档来源的词置信度降一档（见下「代码为准」）。
4. 写到 `/data/glossary/<项目>/<仓>.jsonl`，按项目、按仓隔离。

SDK、模型、区域、API 或提示词变化会使构建指纹失效，触发全量重建；失败保留旧表且不更新指纹。
定时刷新与本地仓上传均遵循同一选择；文件上限也计入构建指纹，改变上限需全量重建。
排队任务拿锁后加载当前配置及解释器。详见 [`../dual-sdk_zh.md`](../dual-sdk_zh.md)。

OpenAI 离线术语表每批默认最多 **400 次模型调用**，可用 `GLOSSARY_MAX_TURNS` 覆盖；
普通批次仍按最多约 59 页的读取预算分组，额外轮数用于超大单文件和后续生成。
每次批处理调用保留 1200 秒超时；流式超时或连接中断使用有限重试，失败保留旧产物。
在线问答的 `agent.maxTurns` 单独配置，不随术语表上限调整。

**查询期（会话 microVM）**——两个只读工具（注册名带 `codegraph_` 前缀）：
- `codegraph_glossary_index`：agent 在开局按需调用一次，取一份轻量对照（中等及以上置信度的词条）——是工具调用，非自动注入上下文。
- `codegraph_glossary_lookup`：按**中文词**或词条 id（`concept_id`）查完整符号集（含低置信的）。
- 拿到英文符号后，照常走 `codegraph_search_files` / `codegraph_symbol_search` / `codegraph_read_file` 实际查看代码取证。

## 三条硬规则

- **代码为唯一依据**：候选文件包括代码、配置表和支持的文档格式（中文常在注释或文档里），
  但**文档与代码冲突时以代码为准**——文档来源的词条置信度降一档，同一词条下代码恒高于文档，
  文档词降级后若仍达到中等置信度且有符号，也可能进入轻量 index，使用时仍须读取代码核实。
- **不臆造**：grounding 校验要求中文别名在其来源文件中出现，模型臆造的别名丢弃。
- **不破只读边界**：构建期引擎是「不跑引擎」约束的明确例外（离线、无会话、无用户输入），
  受工具只读限制、产物只读服务与 grounding 校验约束；取证文本会发送至 Bedrock 模型。
  详见 `invariants.md` §6 与 `AGENTS.md`「构建期引擎」。

## 实测效果与边界

测试样本：某大型开源中文游戏框架（C#/Unity 全栈，约 1.4 万个文件），
中文注释规范、概念密集，代表「中文项目」这类高价值场景。

**规模与成本（实测）：**
- 全量抽出 4881 条记录 / 2634 个词条。
- 历史 Claude 首次全量约 $372（Opus 4.8，index 主机上的离线构建调用 Bedrock）；
  配置不变时按代码 diff 增量。SDK / 模型 / API 切换需要重新全量，OpenAI 成本需单独评估。

**效果：**
- 中文业务词经术语表对应到助手难以臆测的项目专属命名（内部缩写、
  模块前缀、历史叫法），据此定位到相关实现代码。
- 术语表只供参考，与助手自身的判断一起用；结论仍以实际查看代码为准。

**价值边界：**
- 代码里中文和英文符号挨在一起时（比如注释、配置表表头）效果最好，
  能从「只搜到中文注释」找到对应的英文实现代码。
- 术语表给出的对应可能不准、或只对应到某个局部符号而非整体，因此不作为依据，仅供参考。
- 纯英文 / 无中文项目：仍可能生成符号词条并产生费用；没有中文别名时不能改善中文映射，
  问答仍可使用常规代码检索。
